# @deepseek-ai/dsh-budget-ceiling

[English](README.md) | 中文

## Summary

本包为每次会话添加一个硬性支出门槛。当某个会话已消费的提供方用量令牌（输入、输出、缓存与推理）达到配置的上限时，该会话的下一次工具调用会被拒绝，并返回一条稳定、模型可见的拒绝字符串。上限是一个可选的 `budgetCeiling` 配置值：缺省时门保持惰性，包在所有 base-backed 配置中无害启动。计数器从会话的持久化日志重放，因此在 Host 重启后也绝不会失败放行。

<a id="use-this-package"></a>
## 使用本包

当部署需要限制单个会话在失控前能消耗的提供方用量时，挂载本插件。该包以惰性状态（未配置上限）随 `dsh` 基础 bundle 发布；通过 overlay 配置上限即可启用。

### 何时选择它

当长时间自主运行的会话一旦超过预算就必须停止时选择它——这是一个成本上限，而非充值。以下情况应避免使用：会话无论支出多少都必须继续时；需要实时查看消耗或余量的常驻读数时（本门在拒绝之前不显示任何内容）；或需要**按模型**或**按请求**的限制而非按会话总计时。

### 配置上限

添加插件行（基础 bundle 已列出该行）并以消耗令牌为单位设置上限：

```yaml
- id: budget-ceiling
  name: '@deepseek-ai/dsh-budget-ceiling'
  config:
    budgetCeiling: 1000000
```

| 字段 | 默认值 | 含义 |
|---|---|---|
| `budgetCeiling` | 缺省（无上限） | 当某会话消耗的用量令牌达到此数量时拒绝一次工具调用 |

生成的[配置目录](../../../docs/config-catalog.zh.md#deepseek-aidsh-budget-ceiling)记录了所有可接受的值。无需配置上限也无需其他配置——未要求上限的无头部署保持门关闭。

### 你会得到什么

配置上限后，在会话的持久化消耗达到该数量后做出的第一次工具调用会被拒绝。被拒绝调用的模型可见结果带有稳定的 `BUDGET_CEILING_DENY` 代码、配置的上限与消耗数值，因此模型和用户能确切看到调用为何被拒绝、以及当时还有多少余量。拒绝是最终性的；后续调用不会重新折返以允许它。

<a id="理解实现"></a>
## 理解实现

<details>
<summary>实现内部——点击展开</summary>

本节解释门如何折返消耗以及在何处作出拒绝决定；可观察行为已在[使用本包](#use-this-package)中完整覆盖。

### 设计理念

- **在所有者拒绝点强制执行。** 门通过 `ctx.tools.guard()` 注册——这是在整个可扩展 `tools/pre-execute` 瀑布之后计算的单调同步所有者拒绝。返回字符串即拒绝该调用，且后续监听器无法将拒绝改回允许。
- **在读取时折返持久化日志。** 计数器从会话的持久化日志重建，而不仅仅来自实时事件。门首次看到的会话从 seq 0 重放；后续每次调用仅重放未消耗的范围，因此即使在冷重启或 Host 重启后上限仍然生效。
- **一个值，一个决定。** 本包拥有自己的计数器与决定；它不读取任何投影注册表，也不调用任何 Remote。`token-meter` 的占用率仍是参考数值，而这里才是据此作出决定的数值。
- **可选项且无默认值。** 上限是可选的配置字段；缺省时门不注册任何内容，包惰性启动，因此未要求上限的部署绝不会因基础 bundle 而加载失败。

### 折返

消耗是 `assistant/message` 事件携带的五个提供方用量桶之和——输入、输出、缓存读、缓存写与推理——其中缺失的缓存与推理桶按零计。`foldEvent` 跳过每个非 `assistant/message` 事件以及每个没有用量记录的消息。

每个会话的重放游标保存在 `WeakMap<Session, ReplayState>` 中，因此仅为门实际折返过的会话创建条目，并随会话对象一起被回收。`ctx.on('session/event')` 会急切地刷新一个会话的计数器，但仅针对门已经看过的会话；读取时的持久化追赶仍是事实来源，并且不会为任何未被读取的会话创建状态。

### 门

注册的 `ToolGuard` 接收受身份保护的调用。**没有** agent 的调用（直接的 `ctx.tools.execute()` 调用者）没有会话，因此不适用按会话的上限，它会原样通过。有 agent 时，门折返该 agent 的会话，并在其消耗令牌达到或超过上限时拒绝，返回稳定的拒绝字符串；否则返回 `undefined` 且调用继续进行。

### 源码映射

| 文件 | 角色 |
|---|---|
| [`src/index.ts`](src/index.ts) | 插件入口：`Config` schema、`name`/`inject`、持久化折返与 `ctx.tools.guard()` 注册 |
| — | 不发布运行时不变式伴侣；计数器对单个门闭包私有，不暴露任何独立的伴侣可观察的、包自有的事件或快照。 |

<a id="模型体验"></a>
## 模型体验

### 拒绝消息

#### 模型看到什么

当会话达到其上限时，被拒绝工具调用的结果是以下稳定字符串（`Error: ` 前缀是工具运行时的自有封装）：

```markdown
Error: BUDGET_CEILING_DENY: session has consumed {consumed} usage tokens, at or above the configured ceiling of {ceiling}.
```

`{consumed}` 是拒绝瞬间会话的持久化消耗；`{ceiling}` 是配置值。不会添加其他模型可见文本，工具 schema 也不变。

#### 令牌影响

在拒绝之前为零令牌。每次拒绝是该工具调用的一个简短保留结果。

#### KV 缓存影响

仅追加；拒绝是单个新的工具结果，不会使现有 KV 缓存条目失效。

## 已知限制与待办工作

<a id="已知限制与待办工作"></a>

这些限制定义了此上限何时不是合适选择。它们是当前包约束，而非任务积压。

- **不翻译、仅英文的拒绝字符串。** 由于它是宿主编写的、模型可见的工具结果，且模型/线上数据保持原样，因此拒绝字符串被有意保持未翻译，即使在中文界面中也以该 harness 的英文呈现。
- **仅拒绝表面。** 在拒绝之前没有消耗或余量的常驻读数；拒绝是此特性出现的唯一时刻。
- **按会话上限，而非按模型或按请求。** 上限是用提供方用量表示的、扁平化的按会话总计；它无法表达按请求或按模型的限制。
- **`token-meter` 占用率不变。** 本包不改变 `token-meter`；该包的占用率仍是参考数值。
- **统计提供方用量，而非花费。** 上限统计令牌，而非成本；折算为货币预算是另一个决定。
