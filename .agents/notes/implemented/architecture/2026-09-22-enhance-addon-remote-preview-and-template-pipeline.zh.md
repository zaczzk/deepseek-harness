# Agent Note: Enhance addon Remote preview and template-first pipeline

Status: implemented

[English](2026-09-22-enhance-addon-remote-preview-and-template-pipeline.md) | 中文

## 问题

composer 的发送前提示词改写需要纯结构化流水线与用户规则集（原则、黄金示例）协同工作。动态客户端打包会拒绝未声明的工作区值导入，而 `dsh.client.external` 并不是特性插件的依赖机制，因此客户端无法导入该流水线；把规则集搬进浏览器则会把用户配置塞进构建产物而非版本化文件。以模型精化为主的流水线无法进行无密钥测试，并且在模型出错时以放行方式失败。composer 块注册表提升的是让 composer 停用的惰性原因块，澄清流程绝不能这样做。接受增强草稿还带来一个问题：谁有权创建随附的目标。

## 决策

`@deepseek-ai/dsh-enhance` 是零依赖纯流水线：规则集校验、一次显式 `resolve(request): Spec` 步骤（路由、深度、小节、改写方向、正文语言）、模板包渲染，以及包校验边界（`validateSections`、`dropUncitedLines`）。确定性模板阶段就是流水线本体；模型精化只是其输出之上的一个可选阶段。模板输出是带标注的降级模式与无密钥测试替身，因此每条路径都无需 API 密钥即可测试。

预览在宿主侧运行，位于 `@deepseek-ai/dsh-enhance-runtime` 的 Typert Remote 面之后（ctx 键 `enhance`），由客户端插件远程消费，方式与 `dsh-client-ui-commands` 消费 `ctx.commands` 相同。规则集以 `.dsh/enhance.yml` 形式留在宿主侧，并在加载时大声失败。预览是瞬态的：不运行模型调用，也不追加任何会话事件；被接受的文本只有在人类以普通消息发送后才对模型可见。后续的模型精化请求会追加一个携带完整请求的可忽略会话事件，以保持模型可见即被记录。

接受是宿主证明的人类输入，并作为一个操作提交：单次原子草稿替换加上可选的 `ctx.goals.create` 调用——与人类 `/goal` 命令使用的服务路径相同。`tool-goal/authority.ts` 管控的是面向模型的目标工具，而不是在人类手势之上发起的服务调用。目标完成标准保存在目标 seam 中；待办种子以 `todo_write` 指令的形式随被接受的文本一起传递。增强器不保留任何标准存储或待办状态。

澄清芯片以锚定浮层的形式出现在增强弹层中，遵循 slash 选择器 +4px 对齐模式，并且绝不锁定输入面。`ComposerBlock` 是 composer 惰性原因注册表，不用于此场景。

## 考虑过的替代方案

**让客户端打包导入纯核心。** 动态构建预设会拒绝未声明的工作区值导入，而 `dsh.client.external` 并不是特性插件的依赖机制；一旦规则集位于宿主侧，共享模块行只会让浏览器物化耦合到宿主库而毫无收益。

**以模型精化为主、模板兜底的流水线。** 每次请求都要花费一次模型调用，无密钥测试会去模拟主路径而不是真实执行它，并且模型失败会拖累常见情形。模板优先让常见情形零成本，精化成为真正的增强。

**通过 `ComposerBlock` 实现澄清芯片。** 该注册表的契约是禁用消息输入的惰性原因；本插件绝不能锁定 composer，因此芯片改为弹层状态。

**为目标创建新增一条派发权限路径。** 目标服务的 `create` 已经是 `/goal` 背后有据可依的人类路径；接受预览同样是宿主证明的人类输入，第二条权限路径会在目标 seam 旁制造第二个写入方。

**在内存中维护客户端变体历史。** 草稿会在会话切换后存活；变体通过既有草稿恢复通道以不透明 composer 状态随草稿持久化，并且不为装饰性状态引入任何新的会话日志 schema。

## 影响

精化阶段的切片只扩展 `enhance-runtime` 与核心的校验边界；`GenerateOptions.purpose` 会新增 `enhance` 成员并在同一次变更中更新每个消费方，尝试事件承载于可忽略的信封数据之上，并同步更新两个 SDK 投影。`/enhance` 命令保留自己的规则集加载，直到统一化切片把它移到服务上；这一重复记录在两个包的 README 中。客户端测试负责原子替换与逐字节丢弃属性；共享无密钥夹具集驱动单元、组合与录制会话三层。包 README 逐字固定模板的模型可见字面量。
